## 5. Runtime Security Boundaries Enforced On-Chain (`Percolator/Program.lean`)

1. **Canonical Program Pinning & Anti-Aliasing:** Exact 32-byte pinning of SPL Token (`Tokenkeg...`), Token-2022 (`TokenzQd...` where supported), System Program (`1111...`), and `Sysvar1nstructions` + `ctx.dex` (in `LimitMatcher`), plus strict `ABI.nonDupMarker` checks and `userTok != vaultPda` / `feeVaultTok != vaultPda` anti-aliasing.
2. **Bankrupt Settlement Guard & Deadlock Freedom (`#109` / PR #8 / `#110`):** `settleAndRefreshLeg` enforces `allowBankrupt = false` on all non-liquidation paths (`RefreshLeg`, `Trade`, `TradeWithMatcher`, takeover liquidator), blocking silent `insFronted` write-offs (`Custom(107)`). In `handleLiquidate`, `checkAllLegsFreshLoop` runs on all solvent legs (`shortfall == 0 && (freeCap > 0 || legLock > 0)`) to preserve anti-selective-liquidation while letting any bankrupt leg liquidate immediately without a 2-bankrupt-leg deadlock.
3. **Post-`liqFee` Partial-Liquidation Solvency & `liqFeeBps` Wraparound Guard (`#107` / PR `#10`):** `CreateMarket` enforces `liqFeeBps <= mmBps` (`Custom(103)`) so `liqAtP5` cannot wrap mod `2^64`, and any partial liquidation (`remRaw > 0`) enforces `remEff > 0 && postAvail > 0 && postEq >= remMm && remMm >= minMm` (`Custom(103)`), eliminating zero-capital post-fee zombie legs and notional-vs-margin unit mismatches.
4. **Self-Made Market Overflow Immunity & `MAX_MKT_NOTIONAL` (`#110`):** `MAX_MKT_NOTIONAL = 100_000_000_000_000_000` (`$100B` at E6) is enforced in `CreateMarket`, `UpdateOracle`, AND `Trade(mode=0)` (preventing post-`OI==0`-snap notional bypasses that could brick `UpdateOracle`), paired with saturating settlement arithmetic (`mulDiv64Sat`, `mulDiv64CeilSat`, `creditSatGain`) and `qty <= legCloseCap` bounds across `mode=1/2/3`.
5. **Exact Account Sizes, Full Zero-Init & Permanent `MAGIC_CLOSED`:** Every handler enforces exact `dataLen` (`Dex` 208 B, `Market` 416 B, `Portfolio` 976 B, `InsReceipt` 88 B, `LimitBookCtx` 896 B), zeroes freshly initialized buffers via `zeroWordsLoop`, and stamps `MAGIC_CLOSED` (`0x44454144`) on `CloseAccount` to permanently block same-tx revival.
6. **Outage-Resilient Cross-Backing, Pure-ADL Bankruptcy, Unclamped `mode = 1` Exits & Instant Empty-Market Oracle Snap (`#113`):**
   - `handleLiquidate` uses **Pure ADL on bankruptcy (`$0` direct `I_m` draw)**, reserving `I_m` strictly for async cross-backing fronting (`insFronted`).
   - `handleUpdateOracle` and `OracleAdapter.handleCrank` apply `dt == 1` half-step pacing (`maxMoveBps >>> 1`) when `OI > 0` (5–8 slot censorship = `0` bad debt), **snap straight to live spot in 1 slot** when `OI == 0 && rawBasis == 0`, and stamp `MktOff.lastRampSlot` (bytes `152..159`) on saturated ramp moves (`diff >= 75%` of `maxAllowed`) to auto-pause new `I_m` fronting for `RAMP_FRONT_COOLDOWN = 2` slots while leaving all trades open.
   - Bilateral `mode = 1` closes (auto-routed by `mode = 4`, plus limit-guarded `TradeWithMatcher` / `LimitMatcher` closes) allow unclamped real-price repricing and work even when an oracle is stale, while `mode = 0/2/3` opens/hand-offs remain clamped to `maxMoveBps`.
